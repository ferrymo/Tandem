# Tandem

面向多团队、多项目的人与 AI Agent 协作平台。人确定目标、做关键决策，Agent 团队负责设计、开发、测试与交付。

> 2026-11-14 产品整体重构：项目、文档、任务、分析、Agents、连接器、后台管理七个入口。新增本地项目任务、三类文档空间、批量工时与资源时间轴，当前实现与验收边界见 [08 产品重构](docs/08-产品重构与验收.md)。旧 T 组交付证据保留在 [07](docs/07-一期实现与验收.md)，生产发布仍需适配和验收。

## 本地运行

使用本机 Node.js 24（24.11+）、pnpm 10.34.9 与 Docker Compose。命令在仓库根目录执行。

```bash
pnpm install --frozen-lockfile
pnpm local:init
pnpm db:up
pnpm db:bootstrap
pnpm db:migrate
pnpm dev
```

打开 <http://127.0.0.1:3000>。主服务同时提供页面和 API；Worker 无 HTTP 端口。初始化生成随机本地密码，不覆盖已有 `.env`；PG 只映射到本机 `55432`。

登录继承协作系统账号，不提供本地密码注册。按 [05 协作基础与认证](docs/05-协作基础与认证.md) 配置现有站点，或按 [06 本地禅道接入](docs/06-本地禅道接入.md) 启动本机 Docker 禅道。本机已使用开源版 22.7 完成真实账号登录、空间创建与 T 组三人初始化；凭据保存在被忽略的 `.env.zentao.local`。创建空间不会自动获得项目授权或开始执行。

```bash
pnpm check             # 依赖边界、ESLint、类型、单元测试
pnpm test:integration  # 创建独立测试库，验证 PG/队列/Worker，结束后清理
pnpm test:work-management # 隔离 PG：本地业务、权限、角色、附件元数据、工时与撤权
pnpm test:models       # 隔离 PG + 本地模型替身：加密凭据、三种协议、Worker 渠道路由
pnpm test:connectors   # 隔离 PG + 真实 MySQL + 禅道 HTTP 替身：个人授权、只读事务、精确任务 ACL
pnpm build             # Web、Worker、MCP 生产构建
pnpm test:collaboration # 隔离数据库 + 测试协作服务的真实 HTTP 回归，先 build
pnpm test:projects      # 项目、草案版本、原身份和撤权集成
pnpm test:capabilities  # 技能、MCP、个人凭证及 Worker 范围集成
pnpm test:delivery      # 可恢复运行、审批关联和部署回执集成
pnpm test:execution     # 真实 Docker 测试、构建、健康检查与回滚
pnpm test:delivery:real # 本机真实模型交付验收，有模型消耗及本地部署写入
```

浏览器测试、容器运行、备份恢复及排错见 [04 开发基础与本地运行](docs/04-开发基础与本地运行.md)。

本地禅道与 Tandem 启动后，运行 `pnpm test:zentao` 验证真实登录、身份连接、已有空间与退出撤销；凭据配置见 [06 本地禅道接入](docs/06-本地禅道接入.md)。该命令不创建空间。

在“项目”创建本地项目、维护团队职责和模块，到“任务”安排工作并批量登记工时；“文档”选择项目、团队或个人空间；“分析”按人、项目或团队查看每日计划与实际。

查看完整测试场景时，先启动本机禅道和 Tandem，再运行：

```bash
pnpm data:seed --plan   # 核对场景定义
pnpm data:seed --apply  # 创建独立测试空间与真实本机测试账号，可重复运行
pnpm data:verify        # 用各成员真实登录，核对权限、附件和资源工时
```

命令限定本机 Tandem `127.0.0.1:3000` 与禅道 `127.0.0.1:8088`，使用 `.env.zentao.local` 中的本机管理员凭据。准备 8 个项目、36 个任务、12 篇文档、6 个附件和 34 条工时；重复运行会核对既有记录，发现人工修改即停止。测试账号的随机密码保存在被 Git 忽略的 `.env.work-fixture.local`，导入清单和验证报告在 `data/work-fixture/`。体验路径、日期范围、可见性及准确对账值见 [09 测试数据与体验指南](docs/09-测试数据与体验指南.md)。

禅道项目在“连接器”绑定并显式授权；Skills、MCP 与工具授权在 Agents 的能力页签。外部写操作仍先形成草案，由 Worker 使用原账号执行。附件默认保存在独立的 `data/attachments/`，可通过 `TANDEM_ATTACHMENT_ROOT` 指定共享持久目录，下载与删除均重新核验资源权限。

“连接器 → 连接器配置”可保存本人禅道账号、API 密码与数据库只读密码，测试连接并按需读取授权项目和任务。连接只接受服务配置允许的站点和数据库主机，数据库账号若有写权限会拒绝使用；读取结果保留来源与有效期，不导入本地业务表。仅更新凭据时，留空保留本人原值；修改连接配置后须重新填写全部三项授权。实际客户禅道及数据库仍需使用授权测试账号验收。

在“后台管理 → 大模型”登记渠道、协议、模型与 API Key，保存后可发起少量 Token 的真实调用测试；再在“Agents → 运行与执行记录 → 配置 T 组”为三个角色选择渠道模型。运行固定渠道版本，修改渠道后须重新选择。也可在被忽略的 `.env` 中设置 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY` 作为部署默认渠道。

隔离执行仍需配置 `TANDEM_EXECUTION_IMAGE` 与共享产物目录 `TANDEM_ARTIFACT_ROOT`；示例见 `.env.example`。执行镜像须预先拉取，环境变量修改后重启对应进程。当前执行目标是自包含 Web Demo 和本地演示发布，生产环境发布适配器尚未实现。

`pnpm test:product` 使用真实页面、禅道与 Worker 验证协作功能；`test:delivery:real` 使用已配置模型验证 Demo、审批部署和回滚。两者会写入专用本机验收对象，报告存于被忽略的 `data/acceptance/`；后者按报告恢复，避免重复派活。运行前确认本机 `:8088` 测试系统、账号及模型配置，勿指向生产站点。步骤、API 与证据见 [07 一期实现与验收](docs/07-一期实现与验收.md)。

## 默认团队：T 组

由三个 Agent Bot 组成，可整组派活，也可指定成员，承担产品开发、项目交付和可运行 Demo。

| 角色       | 职责                                           |
| ---------- | ---------------------------------------------- |
| 产品设计师 | 需求与验收标准、UI/UX 设计、体验与视觉验收     |
| 技术架构师 | 系统与接口设计、部署/监控/回滚方案、技术复核   |
| 研发工程师 | 开发、测试、修复、获批部署、健康检查与必要回滚 |

交付必须有源码或产物、运行入口、验证证据和已知限制。Demo 标明模拟范围；要求上线的目标须完成部署及健康检查。

## 一期目标

- **项目协作**：项目分组与完整资料、项目职责矩阵、模块、本地任务、时间轴、批量工时与每日资源分析。
- **文档空间**：项目、团队、个人范围，Markdown 编辑、版本保存、独立本地附件与范围授权。
- **T 组执行**：阶段协作、持久队列、预算、暂停与恢复、草案审批、基本隔离执行与预览。
- **能力管理**：安装、管理和使用 Skills；配置 MCP Server，按团队、成员和项目授权工具。
- **交付闭环**：从目标到设计、实现、交叉验收、获批部署与结果验证。

后续扩展插件执行宿主、沙箱实例生命周期、RAG 检索、日历/请假容量与自动派活推荐。当前注册配置与实际执行能力的边界见 08。

## 目标架构

```text
浏览器 / MCP 客户端
          │
Next.js 主服务：Web + API，单进程、单 HTTP 端口 :3000
          │
PostgreSQL + pgvector：自有资产、持久队列、知识索引
          ▲
独立 Worker：消费任务，无 HTTP 端口
          │
隔离执行环境：代码、测试、预览与部署工具
```

前端采用 Next.js + antd；领域、应用服务与适配器按模块分层。主服务和 Worker 共享业务代码，按不同进程运行；文件产物使用文件卷或对象存储。

- **事实边界**：本地项目、任务、工时及文档由 Tandem 管理；禅道来源记录仍以外部系统为事实源，独立展示，不复制整库。
- **对接边界**：外部系统经统一端口接入，业务页面不依赖具体系统术语或 SDK。
- **执行边界**：产品内 Agent 的对外写入与发布须经草案审批；Skills、MCP 和执行环境均受用户及项目授权约束。
