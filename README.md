# Tandem

面向多团队、多项目的人与 AI Agent 协作平台。人确定目标、做关键决策，Agent 团队负责设计、开发、测试与交付。

> 当前已建立工程基础，并实现账号认证、工作空间与成员权限、默认 T 组和六入口工作台。项目读取、派活执行、草案及 Skills/MCP 管理仍在开发。

## 本地运行

要求 Node.js 22.13+（仓库固定 22.23.1）、Corepack、Docker Compose。命令在仓库根目录执行。

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm local:init
corepack pnpm db:up
corepack pnpm db:bootstrap
corepack pnpm db:migrate
corepack pnpm dev
```

打开 <http://127.0.0.1:3000>。主服务同时提供页面和 API；Worker 无 HTTP 端口。初始化生成随机本地密码，不覆盖已有 `.env`；PG 只映射到本机 `55432`。

登录继承协作系统账号，不提供本地密码注册。按 [05 协作基础与认证](docs/05-协作基础与认证.md) 配置现有站点，或按 [06 本地禅道接入](docs/06-本地禅道接入.md) 启动本机 Docker 禅道。本机已使用开源版 22.7 完成真实账号登录、空间创建与 T 组三人初始化；凭据保存在被忽略的 `.env.zentao.local`。创建空间不会自动获得项目授权或开始执行。

```bash
corepack pnpm check             # 依赖边界、ESLint、类型、单元测试
corepack pnpm test:integration  # 创建独立测试库，验证 PG/队列/Worker，结束后清理
corepack pnpm build             # Web、Worker、MCP 生产构建
corepack pnpm test:collaboration # 隔离数据库 + 测试协作服务的真实 HTTP 回归，先 build
```

浏览器测试、容器运行、备份恢复及排错见 [04 开发基础与本地运行](docs/04-开发基础与本地运行.md)。全局 pnpm 异常时继续使用 `corepack pnpm`，Windows 也可使用 `scripts\pnpm.cmd`。

本地禅道与 Tandem 启动后，运行 `corepack pnpm test:zentao` 验证真实登录、身份连接、已有空间与退出撤销；凭据配置见 [06 本地禅道接入](docs/06-本地禅道接入.md)。该命令不创建空间。

## 默认团队：T 组

由三个 Agent Bot 组成，可整组派活，也可指定成员，承担产品开发、项目交付和可运行 Demo。

| 角色       | 职责                                           |
| ---------- | ---------------------------------------------- |
| 产品设计师 | 需求与验收标准、UI/UX 设计、体验与视觉验收     |
| 技术架构师 | 系统与接口设计、部署/监控/回滚方案、技术复核   |
| 研发工程师 | 开发、测试、修复、获批部署、健康检查与必要回滚 |

交付必须有源码或产物、运行入口、验证证据和已知限制。Demo 标明模拟范围；要求上线的目标须完成部署及健康检查。

## 一期目标

- **协作工作台**：关注、Agents、任务、观察、连接、能力六个入口，支持多项目聚合、派活和任务线程。
- **T 组执行**：阶段协作、持久队列、预算、暂停与恢复、草案审批、基本隔离执行与预览。
- **能力管理**：安装、管理和使用 Skills；配置 MCP Server，按团队、成员和项目授权工具。
- **交付闭环**：从目标到设计、实现、交叉验收、获批部署与结果验证。

后续依次扩展 Skills 自主积累与执行沙箱管理、项目知识检索与多项目执行治理、完整负载分析与派活推荐。具体版本范围见产品文档。

## 目标架构

```text
浏览器 / MCP 客户端
          │
Next.js 主服务：Web + API，单进程、单 HTTP 端口 :3000
          │
PostgreSQL + pgvector：自有资产、持久队列、知识索引
          ▲
独立 Worker：消费任务，无 HTTP 端口
          │
隔离执行环境：代码、测试、预览与部署工具
```

前端采用 Next.js + antd；领域、应用服务与适配器按模块分层。主服务和 Worker 共享业务代码，按不同进程运行；文件产物使用文件卷或对象存储。

- **事实边界**：外部协作系统是项目、任务、状态与工时的唯一事实源。Tandem 保存团队、运行、草案、文档和产物等自有资产，不复制业务库。
- **对接边界**：外部系统经统一端口接入，业务页面不依赖具体系统术语或 SDK。
- **执行边界**：产品内 Agent 的对外写入与发布须经草案审批；Skills、MCP 和执行环境均受用户及项目授权约束。
