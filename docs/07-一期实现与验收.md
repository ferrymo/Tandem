## 2. 运行配置

工程初始化、数据库和启动见 [04](04-开发基础与本地运行.md)，账号与空间见 [05](05-协作基础与认证.md)，本机协作系统见 [06](06-本地禅道接入.md)。统一使用 `pnpm`。

主服务在 `:3000` 同时提供 Web/API，Worker 独立进程消费 PostgreSQL 队列，无 HTTP 端口。生产启动前先构建：

```bash
pnpm build
pnpm start
# 在另一终端启动
pnpm start:worker
```

模型及执行配置保存在被忽略的 `.env`，不将 Key 发到聊天或提交 Git：

| 配置                     | 含义                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| `MODEL_BASE_URL`         | 兼容 Chat Completions 的服务基址，例如 `https://model.example.com/v1`；适配器追加 `/chat/completions` |
| `MODEL_NAME`             | 默认模型名称，角色配置可指定模型                                                                      |
| `MODEL_API_KEY`          | 模型密钥，仅传入 Worker                                                                               |
| `MODEL_ALLOW_HTTP`       | 仅可信测试环境显式允许 HTTP；默认不允许                                                               |
| `TANDEM_ARTIFACT_ROOT`   | Web/Worker 共用的产物目录；分进程启动建议使用同一绝对路径                                             |
| `TANDEM_EXECUTION_IMAGE` | 预先拉取的固定 digest 执行镜像，参考 `.env.example`                                                   |
| `MCP_ALLOWED_ORIGINS`    | 管理员允许的 HTTP MCP origin，逗号分隔                                                                |
| `MCP_ALLOWED_IMAGES`     | 管理员允许的容器 MCP 镜像 digest，逗号分隔                                                            |

修改环境后重启对应进程。模型三项未齐全时页面显示“待配置”，不能把该状态当成成功运行。Web 不接收模型 Key 或管理库连接，Worker 使用独立数据库账号。会话加密密钥需要持久保存，变更后旧凭据不可继续解密。

执行容器使用非 root、无网络和资源限制，不挂载宿主 Docker socket，不注入数据库、会话或模型密钥。镜像与产物目录可用不代表生成产物已经通过测试。

当前预览入口是**单 HTML、内联 CSS 与经典 JavaScript、纯内存状态**，刷新后清空。受保护的 sandbox 不保留同源身份，不支持外链资源、ES 模块、网络 API 或浏览器持久存储。源码和 Node 测试可多文件，由无第三方依赖的 Node 构建将同一份受测业务源内联到最终入口。执行器检查构建后的入口并保存静态兼容性证据；它不代替浏览器交互验收，也不替代 CSP、会话和项目授权。

## 3. 使用与权限

1. 使用真实协作账号登录，由指挥官创建空间并初始化 T 组。
2. 在“连接”绑定账号可见项目，显式授予空间成员及 T 组挂靠人项目 `viewer`/`editor` 权限。空间成员身份不会自动获得项目权限。
3. 在“能力”安装并启用技能，按项目、团队及角色绑定固定版本；配置 MCP 后先测试，再逐工具分类授权。个人凭据单独加密保存。
4. 在“任务”读取实际任务，提交创建、修改、状态或工时草案；在“关注”或“任务”审阅当前版本。
5. 在“Agents”配置 T 组并填写目标、验收条件和预算；在“观察”查看阶段、事件、文档、预算与产物证据。

外部项目、任务、状态和工时只从协作系统读取，本地线程、运行、草案、文档和产物属于 Tandem 自有资产。聚合缓存为 15 秒，键包含身份、资源范围和项目缓存版本；命中前重新核权，写入后跨进程失效。

运行权限取发起人与团队挂靠人的授权交集。MCP 写入和部署要求双方均具备项目写权限，并在发送前重新核验上游权限；审批人不能替换原身份提权。查询、下载、续跑、审批和工具调用均重新检查资源范围。撤权、停用或退出会阻止后续使用，已经发生的外部动作不会被宣称撤销。

技能版本和工具 revision/schemaHash 随运行冻结。升级不静默替换进行中的版本；停用或撤权仍会阻断后续调用。技能按需读取资源并检查声明权限与执行依赖，缺少依赖时明确失败。MCP 连接测试只初始化和发现工具，不调用业务工具；`unknown` 分类不能直接执行，写工具进入统一草案。

技能读取记录包含角色、阶段、固定版本、路径、实际提供内容的 hash、字节数及截断标记；版本绑定本身不证明资源已被读取或使用。复核文档区分当前源码问题与预览后的实测事项，系统执行证据只说明构建、测试命令和入口检查的实际结果。

## 4. 状态与恢复

### 草案

草案依次记录 `pending`、`approved`/`rejected`、`executing`、`succeeded`/`failed`/`unknown`。批准绑定内容版本、原会话和目标；修改生成新版本，必须重审。批准与队列入库在同一事务完成，Worker 使用租约和执行令牌防止重复推进。

运行发起人重新登录后可创建新的部署草案；执行使用该草案冻结的有效会话，身份须匹配原发起人，且发起人与团队挂靠人均须保留项目写权限，并重新核验上游授权。审批人的会话不能代替执行身份。

`approved` 仅表示获准，`executing` 仅表示正在执行；只有收到成功回执才能显示成功。外部状态版本冲突、撤权等明确失败保留原因，重新修改提案后再审批。网络超时且无法确认外部效果时保留 `unknown`，不盲目重试；先在事实源核对。

部署结果未知时，运行详情提供“核对实际发布状态”：读取持久发布记录并执行 HTTP 健康检查，能确认则恢复回执；没有记录时需显式确认未发布，才能重新提案。存在记录但健康检查不可用时继续保留未知。MCP 写草案尚未得到成功终态时，运行保留待审批检查点，续跑不会绕过审批继续调用模型。取消运行会阻断尚未发送的关联草案。

### T 组运行

| 状态                   | 含义与处理                                       |
| ---------------------- | ------------------------------------------------ |
| `queued` / `running`   | 已排队 / 正在推进当前阶段，尚未完成交付          |
| `paused`               | 已暂停，保留检查点并释放执行容量                 |
| `needs_auth`           | 身份或授权不可用，恢复有效授权后再续跑           |
| `needs_configuration`  | 模型或执行环境缺配置，补齐并重启后再续跑         |
| `needs_decision`       | 预算、工具审批或其他决策阻塞，按原因处理         |
| `awaiting_deployment`  | 产物已验证，等待部署草案执行结果                 |
| `delivered`            | 当前模式的交付条件已满足，仍需查看证据和模拟范围 |
| `failed` / `cancelled` | 明确失败 / 停止后续执行，保留历史证据            |

新运行预算为 5–100 次模型调用、1 万–200 万 token，最大返工 0–5 次。预算按累计使用计数，暂停和续跑不清零。发起人可增加累计上限，不能降低或重置已用额度。队列与检查点持久化；进程重启不等于重新开始。模型输出结束或构建命令退出为零均不能替代产物入口、文件清单、测试、复核及健康检查证据。

页面 token 数是运行预算账本：调用前按输入字节与输出上限预占，取得有效用量后结算，中断可能保留预占，因此不能直接当成供应商账单。长度截断或无效交付 JSON 不进入已完成阶段，保留检查点和累计预算供处理后续跑。

## 5. 产品 API 与对外 MCP

业务 API 为 `/api/workspaces/:workspaceId/product`。全部操作要求有效会话，POST 还检查同源；请求字段和动作以 `apps/web/src/server/product-http.ts` 的严格 schema 为准。

GET 通过 `resource` 选择资源，按需附 `project`、`execution`、`task`、`run`、`page`：

| 类别       | `resource`                                                       |
| ---------- | ---------------------------------------------------------------- |
| 连接与项目 | `connection`、`projects`、`available-projects`、`project-grants` |
| 任务与草案 | `executions`、`tasks`、`task`、`drafts`                          |
| 交付       | `runs`、`run`、`profiles`                                        |
| 能力       | `capabilities`、`capability-bindings`、`capability-usage`        |

POST 通过 `command` 选择操作：项目绑定/授权/撤权，线程消息，草案创建/修改/审阅，运行创建/控制/扩容/部署核对，团队配置，以及 Skills/MCP 安装、版本、启停、授权与调用。任务草案动作仅有 `task.create`、`task.update`、`task.status`、`task.effort`；部署、回滚和 MCP 写入也使用同一草案服务。产物入口为 `/api/workspaces/:workspaceId/artifacts/:runId/...`，预览和下载同样校验项目权限。

`apps/mcp` 是向外提供 Tandem 能力的 stdio Server；`adapters/mcp-client` 是连接外部 MCP 的客户端。客户端启动 `node apps/mcp/dist/index.js`，通过其私密环境传入：

```text
TANDEM_MCP_BASE_URL=http://127.0.0.1:3000
TANDEM_MCP_ACCOUNT=<本人协作账号>
TANDEM_MCP_PASSWORD=<本人密码>
```

服务地址仅接受 HTTPS 或本机 HTTP。工具为 `tandem_workspaces`、`tandem_projects`、`tandem_executions`、`tandem_tasks`、`tandem_runs`、`tandem_drafts`、`tandem_propose_task_change`。最后一项只创建待审阅任务草案，不提供批准或直接执行工具。工具发现不代表业务调用已经验收。

## 6. 验证与证据

2026-11-13，本机使用真实开源协作系统 22.7、Tandem 页面、PostgreSQL 和 Worker，在专用“Tandem 产品迭代验收”项目/“Tandem 验收迭代”完成任务、草案、工时、能力管理链路。页面验收报告保存于被忽略的 `data/acceptance/walkthrough-report.json`，记录每项结果、外部任务读回证据及浏览器错误。验收数据保留供核对，不作为业务演示预置成功状态。

模型接入前的页面复验为 11 项通过、0 项失败、1 项待模型配置，浏览器异常与 HTTP 5xx 均为 0。桌面与手机共 26 张截图及尺寸索引保存于 `data/acceptance/screenshot-manifest.json`。项目、能力、交付的隔离 PG 集成及真实 Docker 执行验收已通过；这些结果分别对应各自范围。

独立界面审查发现并修复编辑内容静默丢失的问题：任务线程、任务/工时草案、技能、工具服务和团队配置统一检查未保存内容，默认继续编辑；成功保存直接关闭。桌面/手机定向复验 16 项通过，报告为 `data/acceptance/forms-report.json`。刷新离开使用浏览器原生提示；应用导航与有索引的浏览器历史先确认再切换。未知旧历史在缺少原生历史索引的浏览器中保留表单并提示手动恢复，不猜测回退偏移。

导航复验为 10 项通过、0 项失败；两个视口仅有一个授权空间，空间切换未执行。主导航、项目切换、真实前后退和旧历史状态均验证，见 `data/acceptance/forms-navigation-report.json`。期间发现同空间后退永久加载，已修复并加入桌面/手机回归。验收脚本提供 `--forms-only` 和 `--forms-navigation-only` 定向模式，不覆盖完整业务报告。

本轮使用真实 `gpt-6.1-terra` 完成 V1、V2“费用拆分”的三角色设计/实现/复核、固定技能资源读取及共享业务源的 Docker 构建和测试。两版均通过受保护 iframe、桌面及 390px 窄屏的计算、错误、重置、键盘提交和 ZIP 下载验收。V1 由本人重新登录后提交新草案并批准，V2 自动提出草案后经页面批准，两次发布均为 `healthy`。再经页面申请并批准回滚，结果为 `rolled_back`；实际入口 HTTP 200、恢复 V1 且交互通过，内容 hash 与 V1 精确一致。

最终 8 项检查全部通过，浏览器异常与 HTTP 5xx 均为 0。V1 累计账本为 27 次调用、254532 token，V2 为 10 次、62481 token；含中断预占，不能等同供应商计费。报告 `data/acceptance/real-delivery-report.json` 保留初验失败、暂停/续跑、预算扩容和逐步交互记录；11 张截图及两版 ZIP 位于 `data/acceptance/real-delivery/`。无障碍已验证键盘提交及 alert/live 状态语义，未运行实际读屏器。

初验发现并修复了以下真实问题，原失败记录保留：

- 预览外链资源受 sandbox/会话限制不可用：统一单 HTML 契约，并检查构建后的最终入口。
- 构建生成 HTML 被提前拒绝：有构建命令时允许生成入口，构建后仍须验证入口存在、内容及预览兼容性；无构建时必须提供源入口，保留路径不可作为预览目标。
- 复核上下文与技能读取审计不足：提供前序文档、实际执行环境/命令和读取记录，同轮资源读取及时更新；设计复核不再把后续浏览器实测当作源码返工事项。
- 模型截断与非法 JSON：明确停止未完成阶段并保留预算，不把不完整内容视为成功产物。
- 本人重新登录后部署误报 `FORBIDDEN`：新增 `0009_deployment_draft_session.sql`，修正草案会话约束并保留原身份、项目写权限和上游复核。迁移前已备份，本机迁移与 `db:check` 通过；新草案获批发布成功，旧失败草案保留。

修复后 `check` 的模块边界、lint、类型检查及 170 项单测、生产构建、18 项基础端到端测试和 `smoke` 通过；执行器最终 Docker 验证通过。交付物中文标签与验证边界提示经桌面/窄屏定向截图复核通过。真实模型闭环与可重复回归分别保留证据，不将替身测试合并解释为真实运行。

```bash
pnpm check
pnpm test:integration
pnpm test:projects
pnpm test:capabilities
pnpm test:delivery
pnpm test:execution
pnpm build
pnpm test:collaboration
pnpm test:collaboration:browser
pnpm test:e2e
pnpm test:mcp
pnpm test:product

```

`test:integration` 及三个模块集成命令使用独立测试库，覆盖权限、版本、队列、恢复与回执；`test:execution` 使用真实 Docker 验证执行器。`test:collaboration` 验证隔离数据库与测试协作服务的生产 HTTP 链路，需先 build。单元/替身测试用于可重复验证异常与并发分支，不代表真实外部系统已验收。

`test:product` 使用本机真实页面与协作账号，会在专用验收对象中创建任务、技能和 MCP 测试记录；`test:mcp` 验证实际 stdio 工具发现和本账号读取。二者从被忽略的 `.env.zentao.local` 读取 `ZT_ACC`/`ZT_PWD`。不要将真实验收脚本指向生产站点。项目准备及只读连接器核验脚本为 `scripts/seed-local-project.ts`、`scripts/zentao-projects-smoke.ts`，均限定可信本机实例。

`test:delivery:real` 同时加载 `.env` 与 `.env.zentao.local`，仅用于本机 `:8088` 专用验收项目。它通过真实页面安装/绑定技能、派活、审阅部署与回滚，实际消耗模型额度并创建本地测试记录；读取 API 仅用于观察证据，不写库或构造产物。脚本按既有报告恢复，避免重复派活；可传 `--prepare-only`、`--baseline-only`、`--watch-minutes=25`、`--screenshots` 限定准备、V1、等待时长和截图。先完成构建并重启 Web/Worker，确认配置及专用测试对象后再运行。
