# 本地禅道接入

本机 Docker 禅道用于验证 Tandem 继承真实协作账号的登录链路。当前范围为身份认证、工作空间与 T 组初始化；项目、任务读取与 Agent 执行尚未实现。

## 部署与启动

要求 Docker Desktop 已启动。在仓库根目录执行：

```bash
corepack pnpm zentao:up
```

打开 <http://127.0.0.1:8088/>。首次启动需要完成官方安装器，容器健康检查通过不等于应用安装完成。

| 配置         | 本地方案                                                                        |
| ------------ | ------------------------------------------------------------------------------- |
| 镜像         | `easysoft/zentao:22.7-20261104`，固定 manifest digest，见 `compose.zentao.yaml` |
| 端口         | `127.0.0.1:8088` → 容器 `80`，仅本机访问                                        |
| 应用数据     | `zentao-data` 命名卷 → `/data`                                                  |
| 数据库       | 镜像内置 MariaDB，`MYSQL_INTERNAL=true`                                         |
| Web 会话     | `PHP_SESSION_TYPE=files`，`ZT_SESSION_PATH=/data/php/session`                   |
| REST 会话    | `ZT_APISESSION_PATH=/data/php/apisession`                                       |
| 数据库管理页 | `ZT_ADMINER_ENABLE=false`                                                       |

MariaDB 仅属于禅道这个外部协作系统。Tandem 仍使用独立的 PostgreSQL + pgvector，不读取禅道数据库。

22.7 的路由会自行设置 Web 和 REST 会话目录，不能只根据镜像的 `PHP_SESSION_PATH` 判断会话已经持久化。Compose 显式设置 `ZT_SESSION_PATH` 与 `ZT_APISESSION_PATH`，将两类会话都写入 `/data` 命名卷；只保留默认临时目录会导致容器重建后掉登录。

首次安装选择完整管理模式，设置公司名和管理员 `admin`，不导入演示数据，不安装 GitFox，不加入社区。按安装器的大小写、数字与符号要求设置密码，并将验收凭据保存在被 Git 忽略的 `.env.zentao.local`；不要写入文档或提交仓库。现有本地安装已完成，无需再次安装或清空数据库。

停止和恢复使用：

```bash
corepack pnpm zentao:stop
corepack pnpm zentao:up
```

停止或重建容器会保留命名卷；不要通过删除数据卷来处理普通启动故障。

## Tandem 配置

按 [04 开发基础与本地运行](04-开发基础与本地运行.md) 初始化 Tandem PostgreSQL，并在被忽略的 `.env` 中设置：

```dotenv
TANDEM_PUBLIC_URL=http://127.0.0.1:3000
TANDEM_IDENTITY_URL=http://127.0.0.1:8088/
TANDEM_IDENTITY_ID=local-zentao
TANDEM_IDENTITY_LABEL=本地协作系统
TANDEM_COMMANDER_ACCOUNTS=admin
TANDEM_IDENTITY_ALLOW_HTTP=true
```

重启 Tandem 主服务后打开 <http://127.0.0.1:3000>，使用相同的禅道账号登录。`admin` 可创建工作空间；空间创建成功后显示产品设计师、技术架构师、研发工程师三个 Agent Bot。

该配置用于在宿主机运行 Tandem。容器内的 `127.0.0.1` 指向容器自身；Tandem 容器不能直接复用此连接地址。`host.docker.internal:8088` 需要配套的宿主机端口绑定与网络方案并重新验收，当前未验证容器至禅道的连接。更换身份站点地址会改变身份实例键，不能直接继承旧地址下的空间权限。

## 重复验证

在被忽略的 `.env.zentao.local` 中配置 `ZT_ACC` 和 `ZT_PWD`，分别填写安装时设置的账号与密码。确认禅道和 Tandem 主服务均已启动后执行：

```bash
corepack pnpm test:zentao
```

该命令仅允许可信本机 HTTP 地址，验证上游登录与身份、Tandem 会话和连接状态、已有空间与三人角色、退出后旧会话返回 `401`。它不会自动创建工作空间；首次验收需在界面中创建。不要将此命令用于生产站点。

## 验收记录

2026-11-13，本机使用真实禅道开源版 22.7 完成：

- REST `POST /api.php/v1/tokens` 返回 `201`，`GET /api.php/v1/user` 返回 `200`，验证账号 ID 为 `1`。
- 禅道与 Tandem 浏览器界面使用同一账号登录。
- 创建“Tandem 本地验收”工作空间，并在同一事务中初始化 T 组三个角色。
- `test:zentao` 通过：读取现有 1 个空间及三人角色，身份连接正常，退出后旧会话重放返回 `401`。
- 重新登录后强制重建禅道容器，并重启 Tandem 生产主服务；刷新原浏览器仍保持登录，原空间和 T 组三人的 ID 均保持一致。`zentao:stop` / `zentao:up` 已实际运行。

本次验收只证明身份与协作基础链路。登录成功和身份连接状态不代表项目读写授权，也不代表 Agent 已开始运行。工作空间数据保存在 Tandem PostgreSQL，禅道账号数据保存在禅道命名卷。

版本来源：[官方 22.7 发布页](https://www.zentao.net/download/pms22.7-86741.html)；接口基线：[官方 22.7 源码](https://github.com/easysoft/zentaopms/tree/zentaopms_22.7_20261103/api/v1/entries)。其他禅道版本与账号策略需单独验收。
